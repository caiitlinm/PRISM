2. How to tag a passage
Assignment is binary and unordered. For each passage, assign every code whose criteria the passage
satisfies. There is no limit and no ranking — no Tag 1, no Tag 2, no judgment about which code a passage is
"most centrally" about.
Most passages will satisfy one or two codes. Some will satisfy three or more. Some will satisfy none, and an
untagged passage is a valid result — not every sentence needs a code.
Where a code carries a direction, record it alongside the assignment (see §3.2). A code assigned without its
direction is incomplete.

A governance passage that both tightens oversight and explains why:
  •​ C07 Governance Tightening/Loosening [tightened]
  •​ C14 Governance, Transparency and Disclosure
A passage can need three or more codes when three or more things are genuinely true of it — see the
DeepMind example under C14. That is uncommon but correct when it happens.


3. Coding conventions

3.1 "Skip" means assign 0
Several exclusion criteria below use the word skip (e.g. "→ skip; note separately"). Throughout this codebook,
skip means do not assign that code to this passage. It never means excluding the passage from the dataset,
dropping the row, or leaving a field empty. Where the study records assignments as a binary matrix, skip means
enter 0 in that code's column.

architecture_replaced (C03) covers a whole measurement or gating architecture being retired and replaced by a
structurally different one — the case the code describes in its inclusion criteria. split and merged (C05) cover a

3.3 C04 facet rule
C04 covers two facets — a shift in verb modality and a shift in a numeric or stated bar. Record which facet
moved:
  •​ modality — the verb register moved and the stated bar did not.
  •​ bar — the stated trigger value moved and the verb register did not.
  •​ both — both moved, in the same direction.
Divergent case. If the two move in opposite directions (the language firms up while the bar loosens, or the
reverse), record the direction of the bar, set facet to both, and flag the passage as ambiguous with the reason
"modality and bar diverge." Do not split the passage into two assignments.

3.5 Change-family codes require two versions
C01 and C03–C07 are change-family: each requires a prior version of the same framework to compare against.
Where no prior counterpart exists for a passage, these six codes are all 0. A commitment appearing for the first
time is not, by itself, a change to anything.
4. The codes

C01 (Code 1). Competitor/Conditionality Clause Introduction

 Code name                  Competitor/Conditionality Clause Introduction

 ID                         C01

 Family                     Change

 Theme                      Conditional Weakening

 Definition                 Passages that introduce or expand language conditioning a lab's safety commitment on
                            what peers or competitors do — i.e. a clause allowing the lab's own commitments
                            (safeguard stringency, deployment timing, or release schedule) to ease if a rival ships a
                            comparable capability without equivalent precautions.

 Inclusion criteria         Explicit reference to competitor or rival behaviour as a condition on the lab's own
                            commitment; phrases like "if a comparable model is released without similar safeguards," "in
                            light of the competitive landscape." Also covers deployment-timing or release-schedule
                            adjustments conditioned on competitor behaviour (e.g. "we may accelerate deployment
                            timelines if a comparable model has already been released") — the same underlying move
                            (a safety-relevant commitment becoming conditional on a rival's actions) applied to a
                            different lever than safeguard stringency.

 Exclusion criteria         Excludes general aspirational softening that does not specifically reference competitor
                            behaviour.

 Direction                  introduced · expanded

 Example                    OpenAI's 2025 v2 Preparedness Framework adding a clause about easing safeguards if a
                            rival ships something comparable without them. (For OpenAI, these are found in 2025.)
                            Note: this instance is the safeguard-stringency flavour of the code. The passage does not
                            address deployment timing or release schedules, but these may appear in other labs'
                            frameworks in relation to competitor developments. A clause conditioning timing or release
                            schedule on competitor behaviour or market developments would equally qualify.

 Counter-example            "We aim to apply these safeguards where practicable."



Retired: C02 — Threshold Tightening/Loosening
Retired 7 August 2026. Merged into C04 Obligation & Threshold Strength Shift. The two were never cleanly
separable: the codebook's own worked examples for both were the same scenario (a pause commitment
softening), and every clean pilot instance was either a verb-modality shift (C04's territory) or a substantive
scope change already covered by C06 Definitional Drift. Passages about a threshold's bar value changing
between versions now go to C04.
The ID C02 is permanently retired and is never reissued.

 Code name                  Threshold Existence Change

 ID                         C03
Family               Change

Theme                Threshold Existence

Definition           Quick test: does the threshold or gate exist at all in this version? (appeared, vanished,
                     or was replaced by a structurally different mechanism.)
                     Passages where a threshold or trigger point appears for the first time with no prior
                     equivalent, disappears entirely with no replacement, or reappears in a later version after
                     being absent. MERGED CODE: combines the former "Threshold Existence Change (newly
                     introduced/appear/disappear)" and "Threshold Introduction/Removal" entries, which the pilot
                     review (20 July 2026) identified as duplicates.

Inclusion criteria   A threshold or category present in one version and simply absent in another, with no
                     reworded replacement standing in its place; a new introduction; a reintroduction after
                     absence; a removal. Also covers an entire measurement or gating architecture being retired

                     only its stringency, numeric value, or wording changes — that is C04 Obligation & Threshold

C04 (Code 3). Obligation & Threshold Strength Shift

Code name            Obligation & Threshold Strength Shift

ID                   C04

Family               Change

Theme                Commitment Firmness & Threshold Strength

Definition           Quick test: the threshold still exists in both versions — did its bar or its firmness
                     move? Quick test for facet: did the verb change (modality), the number change
                     (bar), or both?
                     MERGED CODE (merged with the former C02 Threshold Tightening/Loosening on 7 August
                     2026). Passages tracking whether a commitment's verb modality shifts between mandatory
                            ("will," "shall," "must"), conditional ("will, unless X"), and aspirational ("aim to," "intend to")
                            register across versions, becoming firmer or more vague — OR where a specific numeric
                            bar or trigger value for the same named threshold moves between versions (e.g. ">2x time
                            saved" becoming ">5x time saved"), tightening or loosening the same metric.
                            These two facets often arrive bundled in the same passage. Assign the code once and
                            record which facet moved (modality, bar, or both) per §3.3; do not split the passage into two
                            assignments.

 Inclusion criteria         Modality facet. Any version-to-version comparison where the same commitment's verb
                            strength changes. Signals: "will" becoming "will aim to" or vice versa; "will trigger" becoming
                            "may trigger"; "at our discretion," "provided that," "unless," "except where," "as appropriate
                            given the circumstances."
                            Bar facet. The same named threshold's stated trigger value changing between versions
                            while the threshold itself persists. Signals: a quantity, percentage, multiplier, time window,
                            count, or named benchmark score that appears in both versions against the same trigger
                            and differs between them (e.g. ">2x time saved" becoming ">5x time saved"; "within 24
                            hours" becoming "within 7 days"). The trigger must persist under the same or a directly
                            successor name — a new threshold appearing, or an architecture being restructured, is
                            C03.

 Exclusion criteria         Excludes the competitor-specific case already captured under C01 Competitor/Conditionality
                            Clause Introduction. Excludes a threshold or category stated for the first time with no prior
                            version to compare, or an entire measurement architecture being restructured — that is C03
                            Threshold Existence Change. Excludes a substantive change in WHAT counts toward a
                            persisting threshold's definition (e.g. a capability that used to qualify no longer does, or vice
                            versa) where the trigger's own wording or value does not change — that is C06 Definitional
                            Drift.

 Direction                  tightened · loosened. Facet (required): modality · bar · both. For the divergent case, see
                            §3.3.

 Example                    DeepMind's v1.0 stating it "will pause deployment" upon a Critical Capability Level being
                            reached, versus v3.1 stating it "will evaluate appropriate mitigations" upon the same trigger.
                            [loosened, facet: modality] — Anthropic's v1.0 pause commitment reading as a firm stop at a
                            set capability level, versus v3.3 leaving more room for judgment about timing and
                            competitors. [loosened, facet: modality]

 Coder note                 On the DeepMind example: a first reading may suggest [tightened] because the later
                            wording is more elaborate. It is a loosening — the commitment moved from a definite action
                            ("will pause") to a discretionary assessment ("will evaluate appropriate mitigations"). Judge
                            the direction by the firmness of what the lab is bound to do, not by the specificity of the
                            language describing it.

 Counter-example            "We will publish our framework annually," appearing identically worded across versions —
                            no shift in either modality or bar value.


READ ME — telling three easily-confused codes apart
C08 Frontier AI Risk Definition & Framing, C05 Adding or Dropping a Risk Theme/Domain, and C06
Definitional Drift are frequently confused, since all three touch how a risk concept or category is described. Ask
these questions, in order:
  •​ C08 Frontier AI Risk Definition & Framing — what does the lab say frontier, existential or catastrophic
     risk MEANS, or how does it carve risk into buckets, within a single version?
  •​ C05 Adding or Dropping a Risk Theme/Domain — did a whole category's PRESENCE change
     between versions: tracked in one, gone (or reintroduced) in another?
  •​ C06 Definitional Drift — does the substantive definition of an already-present risk concept narrow or
     broaden between versions, even though the category itself persists in both?
Worked example: OpenAI's 2025 line "Persuasion category risks do not fit the criteria for inclusion" is assigned
C05 [dropped] (Persuasion was tracked in 2023 and is not in 2025) plus C15 Persuasion and Influence Risk
Theme (the passage is still substantively about persuasion). If instead CBRN stayed tracked in both versions
but its definition of qualifying uplift narrowed, that would be C06, not C05 — the category never left.

C05 (Code 4). Adding or Dropping a Risk Theme/Domain

 Code name                 Adding or Dropping a Risk Theme/Domain

 ID                        C05

 Family                    Change

 Theme                     Scope Shift — risk themes being added, dropped, or reintroduced

 Definition                Passages where an entire risk category, domain, or tracked capability area is added,
                           removed, or reintroduced between versions, as opposed to a threshold changing within a
                           category that persists.

 Inclusion criteria        A named category present in one version and absent in another, or a category that
                           disappears in one version and reappears in a later one; language like "no longer tracked,"
                           "new category," "reintroduced." Also covers a single category dividing into several (split) or
                           several consolidating into one (merged).

 Exclusion criteria        Excludes cases where a category's definition shifts but the category itself remains present
                           across all versions — that is C06 Definitional Drift.

 Direction                 added · dropped · reintroduced · split · merged

 Example                   OpenAI's Preparedness Framework dropping the Persuasion category between the 2023
                           Beta and v2 [dropped]; DeepMind's Frontier Safety Framework cutting the Autonomy
                           domain and later folding misalignment work into a single domain in v3.1 [merged]. Pilot
                           example: 2023's single "Model Autonomy" category becoming AI Self-improvement
                           (Tracked), Long-range Autonomy (Research) and Autonomous Replication and Adaptation
                           (Research) in 2025 [split].

 Counter-example           "CBRN remains a tracked category in both versions, but the definition of what counts as
                           CBRN uplift has narrowed."



C06 (Code 5). Definitional Drift

 Code name                 Definitional Drift

 ID                        C06

 Family                    Change

 Theme                     Substantive Narrowing or Broadening of an Already-Present Risk Concept

 Definition                Added following pilot review, 20 July 2026, in response to a question about whether a risk
                           concept defined differently across two versions was already covered elsewhere — it was
                           not. Passages where the substantive definition of a risk concept or category narrows or
                           broadens between two versions of the same framework, even though the concept or
                     category itself is present in both versions and no threshold or category presence changed.
                     Change-family only: requires a prior version to compare against.

Inclusion criteria   The umbrella definition of frontier, catastrophic or existential risk changing in substance
                     between versions (e.g. what counts as "severe harm" expanding or contracting). A named
                     risk theme (e.g. CBRN) remaining tracked in both versions, but what qualifies as an instance
                     of that risk narrowing or broadening (e.g. what counts as "CBRN uplift").
                     Record a direction: [narrowed] = the definition covers less than before; [broadened] = the
                     definition covers more than before.
                     The narrowing/broadening test: can you name one concrete real-world example that
                     would have qualified under the old wording but would not qualify under the new wording, or
                     vice versa? If yes, that is Definitional Drift. If you can only point to different words describing
                     the same real-world cases either way, it is stylistic — see Exclusion criteria.

Exclusion criteria   Excludes a category's presence changing (tracked → gone, or vice versa) — that is C05
                     Adding or Dropping a Risk Theme/Domain. Excludes a numeric or tiered threshold changing
                     while the underlying definition of the risk stays the same — that is C04 Obligation &
                     Threshold Strength Shift. Excludes a risk being moved inside or outside document scope, or
                     handed to another instrument: route that per the tombstone note preceding C11 — to the
                     relevant risk-theme code, to C14 Governance, Transparency and Disclosure, or to C16
                     Evaluation and Risk Management Practices as appropriate. Excludes cases where the
                     definition is worded identically or with only stylistic changes across versions; use the
                     narrowing/broadening test to check.

Direction            narrowed · broadened

Example              A. "CBRN remains a tracked category in both versions, but the definition of what counts as
                     CBRN uplift has narrowed." [narrowed] — assign C13 CBRN Risk Theme alongside. B. A
                     closer call, showing the test in action: a Cybersecurity Critical threshold reading "exploits…
                     across all software projects" in one version and "exploits… in many hardened real-world
                     critical systems" in the next. At first glance this could be read as rewording. Applying the
                     test: can you name something that would have counted before but not now? Yes — a small
                     hobbyist app or non-critical internal tool would have been "software" under the old wording
                     but would not obviously be a "hardened real-world critical system" under the new one. That
                     is a real narrowing, not style. [narrowed]

Counter-example      OpenAI's Preparedness Framework dropping the Persuasion category outright between
                     2023 and 2025 — the category's presence changed, not its definition. That is C05. Also a
                     counter-example for the test itself: two versions that swap "will identify security
                     vulnerabilities" for "will discover security flaws" — no real-world case would qualify under
                     one wording and not the other, so the test says skip it as stylistic (assign 0; see §3.1).



C07 (Code 6). Governance Tightening/Loosening

Code name            Governance Tightening/Loosening

ID                   C07

Family               Change

Theme                Governance Robustness Change

Definition           Added following pilot review, 20 July 2026. Passages where the internal governance
                     apparatus overseeing safety decisions — committees, reporting lines, approval and veto
                     authority — is strengthened or weakened between versions of the same framework.
                     Change-family only: requires a prior version to compare against. C07 is rare — if
                            assigning it more than a handful of times, re-verify each instance names a
                            specific body, reporting line, or authority; general safety-culture language is not
                            C07.

 Inclusion criteria         A body gaining or losing oversight or veto authority (e.g. a Board committee newly given
                            power to "reverse a decision"); a reporting line added or cut (e.g. less direct reporting
                            between Audit and the Board); a committee created, dissolved, or merged; escalation or
                            emergency fast-track procedures added or removed. Record a direction: [tightened] = more
                            oversight, more layers, more veto power, more direct reporting; [loosened] = less oversight,
                            fewer layers, less veto power, less direct reporting.

 Exclusion criteria         Excludes a governance body or process described identically across both versions —
                            assign C14 Governance, Transparency and Disclosure only, with no direction. Excludes the
                            stated reason for a change, which stays under C14's explanatory-language criterion.
                            Excludes cases with no prior version to compare — that is C14 only, not a shift.

 Direction                  tightened · loosened

 Dependency                 C07 requires C14 on the same passage (see §3.4).

 Example                    2025 OpenAI SAG passage adding "OpenAI Leadership can approve or reject these
                            recommendations, and our Board's Safety and Security Committee provides oversight of
                            these decisions" — an approval and oversight layer not present in the 2023 SAG
                            description. [tightened]

 Counter-example            SAG described in near-identical terms in both versions, with no change to who reports to
                            whom or who holds final say — no direction applies; C14 only.

C08 (Code 7). Frontier AI Risk Definition & Framing

 Code name                  Frontier AI Risk Definition & Framing

 ID                         C08

 Family                     Content
Theme                Definition of concepts such as frontier risk

Definition           Passages that tell you what the lab takes AI frontier risk to BE, or why it matters — either by
                     defining the big concept, dividing catastrophic or existential risk into major kinds, or
                     motivating why frontier or catastrophic risk requires attention (most typically, a misuse-type
                     versus misalignment-type split, in each lab's own vocabulary).

Inclusion criteria   [A-umbrella] Defining the big concept. Sentences fixing what catastrophic, frontier or
                     existential risk means, or "unknown unknowns" that may form part of frontier risk. Signals:
                     "we mean," "refers to," "focus on," glossary entries. A sentence without these verbs still
                     counts if it pins down the meaning.
                     [A-framing] Dividing frontier or catastrophic risk into major kinds (e.g. CBRN, misuse,
                     loss of autonomy). If a lab defines frontier risk and also names other risk categories or
                     themes (e.g. CBRN), assign the relevant risk-theme code as well.
                     [A-motivation] Motivating why frontier or catastrophic risk matters, or why the lab is
                     investing in studying or tracking it — opening statements about the state of the field, the
                     stakes involved, or the case for taking the risk seriously, including framing sentences that
                     precede or introduce a fuller definition. Signals: "we believe," "it is critical that," "fallen short
                     of where we need to be."
                     A passage may carry more than one of the three; record all that apply.

Exclusion criteria   Dictionary entry for ONE category ("CBRN: risks of models assisting in… a CBRN threat")
                     → assign the relevant risk-category code only; this code applies only when the passage
                     structures frontier risk as a whole.
                     Definition of a tool, not a risk ("A Capability Threshold is a prespecified level of AI
                     capability…") → skip (assign 0; see §3.1); note separately.
                     Mission or value talk with no connection to frontier or catastrophic risk at all ("we aim to build
                     beneficial AI for all of humanity") → skip. Mission or value talk that motivates why frontier or
                     catastrophic risk specifically matters, or why the lab studies or tracks it, is covered under
                     [A-motivation] rather than skipped.
                     Note: lab-specific proxies or benchmarks used to render a shared risk are not coded —
                     handled later in analytic memos.
                     Clarifying note (added 7 August 2026). A bare label naming the "Unknown Unknowns"

Retired: C10 — Scope of Risks
Retired 7 August 2026. Scope of Risks (INSIDE / OUTSIDE / DEFERRED / DELEGATED) was dropped as its
own code: in practice its [excluded] and [deferred] passages always duplicated C05 Adding or Dropping a Risk
Theme/Domain or C03 Threshold Existence Change, and the code was a frequent source of confusion.
Passages stating that a named risk is in scope, out of scope, deferred, or delegated elsewhere now route as
follows. If the passage is substantively about a specific risk theme (C11 Autonomy/Loss of Control, C12
Cyber-related, C13 CBRN, or C15 Persuasion and Influence), assign that risk-theme code. If it hands
responsibility for a risk to another instrument, policy or body — the delegation case — assign C14 Governance,
Transparency and Disclosure, which carries an explicit delegation criterion for this purpose. If it is about the
practice of monitoring, evaluating or managing that risk, assign C16 Evaluation and Risk Management
Practices. If none genuinely fits, it is correct to leave the passage untagged.
The ID C10 is permanently retired and is never reissued.

C11 (Code 9). Autonomy/Loss of Control Risk Theme
Code name            Autonomy/Loss of Control Risk Theme

ID                   C11

Family               Content

Theme                Ability to act independently, improve, and/or evade developer control

Definition           Model autonomy relates to the level of independent decision-making and action a model can
                     take without human intervention. Risks stem from a model's ability to autonomously
                     accelerate its own capability development, potentially compromising or escaping human
                     control. Passages where the document discusses: an AI system's capacity to execute
                     complex, long-horizon, uninstructed actions that are fully independent; operating without
                     human intervention, enabling scaled misuse; a model developing autonomy and evading
                     developer control; or a model independently acquiring adaptive resources (renting its own
                     cloud servers, etc.), self-exfiltration capabilities, or autonomous replication and adaptation
                     (surviving, making copies of itself).

Inclusion criteria   Language like "progression of autonomy," "loss of control," enabling "actors to run scaled
                     misuse," "self-initiated actions," "fully autonomous agents" capable of "long-term /
                     long-range / long time-horizon planning," model "adaptation" to complex scenarios;
                     intentional model underperformance during checks ("sandbagging"), "autonomous
                     replication," "completes chained actions," initiating high-risk tasks without human instruction,
                     an "autonomous model creating uplift."

Exclusion criteria   Excludes simple triggers that are baseline-level rule-based automation. Note that
                     "autonomy" is adjacent to but separate from "agency" (e.g. defined by AWS as the "scope of
                     actions that an AI model is enabled/permitted to take within an environment, and how much
                     a human bounds an agent's capabilities/permissions").

Direction            None. Record NA.

Example              "In conjunction with a long range autonomy capability, models that could bypass OpenAI's
                     technical safeguards constraining model activity, such as sandboxing or monitoring services,
                     could compromise OpenAI's ability to…"

Counter-example      "The model solves well-specified tasks demonstrating an understanding of programming."
                     (Excluded — medium risk; no demonstration of adaptation or long-term contextual
                     understanding; no ability to replicate or self-exfiltrate; no lack of human controllability; model
                     not adapting to a human attempting to shut it down.)

Code name            Governance, Transparency and Disclosure

ID                   C14

Family               Content

Theme                Senior executive and management committee and board governance; transparency and
                     disclosure to the public; enterprise risk governance as a governance practice; corporate
                     governance and disclosure, including independent oversight

Definition           Passages where the document discusses internal governance practices, a governance
                     function, centralised review processes and decision-making (senior advisory groups and
                     committees), accountability and reporting protocols, Board committees, and third-party
                     audit.

Inclusion criteria   Language like "a Board's Safety and Security Committee providing oversight of these

                     Group, the Board having the option to "reverse a decision and/or mandate a revised course

Code name          Persuasion and Influence Risk Theme

                   self-harm).

                   need not. Note: influence operations and public sentiment manipulation may also be tracked
                     outside frontier risk policies, through product-abuse or trust and safety frameworks, or within
                     cyber-related risk assessments (footnote as applicable).

                     cases), "perception hacking," "generative disinformation," "generate deceptive content at
                     scale." Language like "deceive," "mislead," or "conceal capabilities" in some cases.
